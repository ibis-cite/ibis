# Preview styling candidates, fixed top placement

**Visual concepts only: not implemented and no default selected.** These two
candidates address preview typography and hierarchy separately from the earlier
[placement comparison](preview-placement-636.md). Both keep the existing top
position, selected-reference tray, actual formatter output and preview markup.
Production CSS, TypeScript and native behavior are unchanged.

- **A — Quiet inline:** primary body text, a small muted Preview caption and the
  existing separator. It leaves more room for results.
- **B — Subtly inset preview:** the same type, colour, caption and formatter markup,
  inside an inset soft surface with existing border, radius and spacing tokens.
  It separates the preview more distinctly and consumes more vertical space.

The choice is left open for the user. Neither concept changes formatting rules,
selected-reference order or what the formatter produces.

## Typography and preserved formatting

The current preview inherits the root's 16px size (18.4px with Larger) and coral
citation colour. Both candidates retain the same inherited system font family,
use the existing body role at 14px/20px (16.1px/23px with Larger), normal weight,
and primary `--text` colour. No font is installed or introduced.

The Preview caption uses existing heading size/weight/tracking and label-line
height tokens, with `--muted`. It sits outside `.preview-text`, so it is not part
of the formatter output. The header already names APA; the caption does not
repeat the style name.

The ordinary preview remains exactly:
`(Example & Sample, 2026; 架空 著者, 2026)`.

The multilingual example is generated by the actual APA formatter from synthetic
no-author books. Its exact preview markup is:

```html
(<i>Mémoire x<sup>2</sup></i>, 2026; 記憶と学習, 2026)
```

The probe compared `.preview-text.innerHTML` and `.textContent` with the current
baseline before every capture. Both remain identical across current/A/B in each
case. It also observed the rendered `<i>` as italic and `<sup>` as superscript in
all three treatments. It did not reconstruct or flatten formatted text or alter
punctuation. The long sample's ordering is the formatter's own ordering.

## Space tradeoff

Visible results area includes its heading and padding; these CSS-pixel values do
not count readable references. The existing narrow source uses document scrolling
before the separate #639 containment work, so these measurements are not claims
about a final bounded picker.

| Representative case | Current visible results area | A | B |
| --- | ---: | ---: | ---: |
| Ordinary, 720×480 light normal | 287.7 | 265.7 | 240.7 |
| Long, 720×480 dark Larger | 239.3 | 214.3 | 185.7 |
| Ordinary, 360×320 dark normal | 146.2 | 124.2 | 99.2 |
| Multilingual markup, 360×320 light Larger | 78.6 | 54.4 | 25.8 |

The caption adds hierarchy and some height in A. B's padding, border and outer
inset cost about another 25px at normal text or 28.6px with Larger. The tight
multilingual view exposes little results content in B. These boards deliberately
keep the entire fixed picker viewport so that this cost remains visible.

## Temporary prototype CSS

This CSS exists only in the browser prototype and as evidence text in the
manifest. It is not added to application styles. Both candidates share:

```css
[data-preview-style] .format-preview .preview-text {
  color: var(--text);
  font-family: inherit;
  font-size: var(--type-body-size);
  line-height: var(--type-body-line);
  font-weight: 400;
}
[data-preview-style] .concept-preview-caption {
  margin: 0 0 var(--space-1);
  color: var(--muted);
  font-family: inherit;
  font-size: var(--heading-size);
  line-height: var(--type-label-line);
  font-weight: var(--heading-weight);
  letter-spacing: var(--heading-tracking);
}
```

A adds:

```css
[data-preview-style="A"] .format-preview {
  padding: var(--space-2) var(--space-4);
  border-bottom: var(--border-width) solid var(--line);
}
```

B adds:

```css
[data-preview-style="B"] .format-preview {
  margin: var(--space-2) var(--space-4);
  padding: var(--space-3);
  border: var(--border-width) solid var(--line);
  border-radius: var(--button-radius);
  background: var(--hover-background);
}
```

There are no new colour, font, decoration or shadow tokens. The rules target the
preview container, not formatter descendants, preserving emphasis and script
markup.

## Reproduction and checks

Use the exact source and existing gallery/temporary CSL adapter described in the
[placement report](preview-placement-636.md#reproduction-without-production-edits).
This time **do not move `.format-preview`**. The existing `tray` fixture still
seeds two selected references and three results. The ordinary data is unchanged;
long and markup cases supply the manifest's synthetic CSL plus corresponding
plain search-result fields through the one-off provider. The real App and
formatter worker render every preview; no hand-drawn preview is injected.

For each case, capture the current baseline after the formatter settles. Then
prepend a paragraph with class `concept-preview-caption` and text `Preview` to
the existing preview section, set `document.documentElement.dataset.previewStyle`
to `A` or `B`, and inject the recorded candidate CSS into a temporary style element.
Use the same preview node and match focus/pointer/scroll conditions before every
capture. Compare formatter innerHTML/text, selected keys, tray rectangles and
main DOM order with the baseline. The exact CSS and input data are in the
manifest, so this experiment needs no repository harness or new dependency.

Passed: 12 current/A/B state and markup comparisons; same top DOM order, selected
keys and tray rectangles; computed italic/superscript preservation; no page
errors; same existing font family; no preview shadow; all four PNG encoding/
extension/dimension/hash checks; whitespace and production-source-diff checks.

Not run: Rust/native builds, full checks or fuzzing, as excluded for this bounded
concept task. No clipboard copy was performed. Temporary caption injection and
styling do not establish keyboard, copy ownership, assistive-technology, native
appearance or final implementation acceptance. Coverage is limited to APA,
comfortable density and these four representative contexts; pending/stale/error
previews, 200% scaling, other styles/densities and native platforms remain outside
this comparison.
